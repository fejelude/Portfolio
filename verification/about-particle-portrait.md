# About particle portrait

Original upload was 1672×941 RGB with identical R/G/B channels; it is already monochrome. A local Lanczos sample at 256×144 was encoded as WebP (quality 85, 4,442 bytes) without EXIF, GPS, device, Photoshop or ICC metadata. The original full-resolution photo and placement screenshot are not committed. The image has no obvious readable address, ID or document in its background; the clothing wordmark is retained. Sample data is publicly reconstructable, so the owner should review that choice before merge.

The source is loaded only within 220 CSS px of the portrait. It is decoded once, then sampled into a responsive square-cell lattice. Each cell owns source color, original position and independent displacement/velocity. A resting particle cache is drawn from those cells. On interaction only displaced cells are erased and redrawn; no background photograph is displayed underneath. Local radial repulsion, spring recovery, exponential damping, 120 Hz substeps, displacement limits and exact snapping after convergence keep motion bounded. Density follows displayed width and device capabilities; DPR is capped, and slow frames lower cadence without recoloring or degrading the resting image. No animation loop runs at idle or outside the viewport. Touch uses passive Pointer Events with pan-y/pinch-zoom and never captures a scrolling gesture.

Sources consulted: MDN Canvas optimization, MDN Pointer Events/touch-action, and the Particle-Portrait creative coding example (image sampling and spring return). No third-party source code copied. Verification includes unit and browser smoke tests, screenshot capture, lazy loading, exact recovery, idle draw count, reduced motion, and emulated touch scrolling. Physical iOS Safari and Android Chrome need owner device testing.
