## 3. Restoration procedure

1. Obtain explicit owner authorization and scope (private preview only by default). Confirm the owner and recipient's boundaries and do not infer permission to publish. Read the restricted preservation record in the authorized storage account. Use authenticated Vercel/account tools or an owner-exported encrypted copy; no shared link, public download, client token or secret should be embedded. Mount the persistent backup read-only in a private sandbox with no public ports; do not attach it to the production web root. If the verified backup is unavailable or incomplete, stop.
2. Set `BUNDLE` to the authorized local path to `Portfolio.bundle`. In the private backup directory, run `sha256sum -c SHA256SUMS` (or equivalent SHA-256 check on macOS), compare to the restricted record, then restore to a new private directory. Use `git clone --mirror "$BUNDLE" "$PRIVATE_DIR/original.git"`, `git -C "$PRIVATE_DIR/original.git" fsck --full`, and `git -C "$PRIVATE_DIR/original.git" bundle verify "$BUNDLE"`. Check the saved original main SHA against the record; inspect `git bundle list-heads "$BUNDLE"` and compare ref names/object IDs. Verify the inventory with `git cat-file -e "$ORIGINAL_SHA:$path"` for each original path and scan for unresolved LFS pointers. Do not accept a reconstructed approximation.
3. Create an isolated, access-controlled repository or local worktree with no public remote or automatic deploy integration. In the current approved archive base checkout, after verifying a clean status and recording its SHA as `ARCHIVE_SHA`, create a dedicated **private** restoration branch, for example `git switch -c restore/birthday-private "$ARCHIVE_SHA"`. A future restoration branch is permitted only by the restoration authorization; do not create one in the public repository. Keep the archived public route intact for private-access design; when verifying the original as-is, use a separate private checkout at `ORIGINAL_SHA`.
4. In the private repo, fetch the verified saved commit from the local bundle (`git fetch "$BUNDLE" refs/heads/main`); verify `git rev-parse FETCH_HEAD` equals the recorded `ORIGINAL_SHA`. Use the restricted inventory to restore only feature paths: `git restore --source="$ORIGINAL_SHA" --staged --worktree -- <approved feature paths>`. The angle-bracketed expression is a placeholder, not a literal command. Inspect missing files, exact Git blob IDs and dependencies. Do not wholesale restore the original `index.html`, APIs, database/auth code or `vercel.json`, which would undo unrelated future changes.
5. Use Node 24 (historical CI version), Git, npm, FFmpeg, and Playwright 1.56.1. Install only in the isolated worktree; `npm install --no-save --package-lock=false playwright@1.56.1`; `npx playwright install --with-deps chromium firefox webkit` (use supported engine/OS combinations; historical WebKit runner macOS 15). Review any future dependency/codec differences and keep fixes separate from original files.
6. Recreate only the relevant clean-URL mappings and robots headers in the private preview's routing config; preserve all current unrelated rules. The archive retirement adds redirects for the former album and scrapbook, both extensionless and `.html` forms; remove or override those redirects only in the private preview configuration. Restore original `audio/mpeg` for MP3, `audio/mp4` for M4A/audio-only MP4, correct font/image content types, byte-range media support and noindex/nofollow. Verify both route forms and static asset URLs. Do not make the old production paths public. Keep the new public archive's audio, CSS and JS separate.
7. Restore original feature scripts and HTML from the bundle, including clock, artwork, blossom, garden, lily, album configuration and playback/controller modules; verify audio assets against their saved blobs. The original sequence depends on its audio timeline, not the archive's loop; do not replace it with archive music, alter timing, invent art or rebuild the original from memory. Verify the original start/replay flow and track transitions.
8. Diff restored feature files against saved `ORIGINAL_SHA`; document any intentional compatibility changes. Test against current hosting rules without overwriting unrelated changes. If original behavior is incompatible with current runtime, prefer an isolated compatibility fix with regression tests and preserve the exact backup unmodified.
9. Run the verification commands below and test the complete experience in a private preview. Use local loopback or an authenticated sandbox; the original verification server listens on all interfaces, so run only inside an isolated environment with **no exposed ports**. Disable public deployment automation and public artifact uploads. Do not assume an unlisted URL or robots tag provides access control.
10. Verify explicit authorization and asset access control before any preview URL is shared. Check unauthenticated requests to every old route, extension variant, static asset and metadata/OG endpoint; require denial or the public archive, not private bytes. Inspect deployment aliases, direct CDN/origin paths, cache behavior, repo visibility, branches, tags, history, PR diffs and artifact access. Public Git history may still contain original content; coordinate separately with owner and GitHub support if required. Never claim external copies are retractable.
11. Create a restoration PR only within an authorized private repository to a private target, documenting the verified source, changes, tests, known limitations and rollback commit. Do not make the public archive inaccessible or automatically merge/deploy. The reviewer must explicitly authorize any intended access scope; no restoration of public access is implied by this guide.

## 4. Future secure private access (design only)

Keep the existing public archive at its URL. An optional future private experience should be served from a distinct protected origin or server-side route with established authentication, per-request authorization and explicit access grants/revocation. Keep original media, fonts, scripts, source maps, artwork and metadata in private storage; deliver only after authorization, or issue short-lived scoped signed URLs where appropriate. Do not place the files in a public static folder, CDN or public Git history. Use private/no-store cache controls, noindex/nofollow in addition to authorization, no-referrer, generic public metadata, and protected preview/CI access. Test unauthenticated requests, stale/revoked sessions, direct asset requests, cache isolation and logout. Use a server-side secret manager; no credentials or access codes in client code or public docs. Do not implement this access mechanism as part of archival work.

## 5. Verification checklist and commands

The exact original commands below come from the saved birthday, album and compendium CI workflows. Run in the isolated restored original worktree, not in public CI. Install Node 24 and Playwright first as above. Linux virtual audio setup (original CI): `sudo apt-get install -y pulseaudio ffmpeg`, `pulseaudio --start --exit-idle-time=-1`, `pactl load-module module-null-sink sink_name=ci_audio`, `pactl set-default-sink ci_audio`. Use a disposable runner, not a production machine.

```sh
node --test tests/birthday*.test.mjs tests/album*.test.mjs tests/compendium*.test.mjs
node --test tests/*.test.* api/sofra/*.test.js
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install --with-deps chromium firefox webkit
BIRTHDAY_ENGINES=chromium,firefox node verification/birthday-lily-smoke.cjs
BIRTHDAY_ENGINES=chromium,firefox node verification/birthday-smoke.cjs
ALBUM_ENGINES=chromium,firefox node verification/album-smoke.cjs
COMPENDIUM_ENGINES=chromium,firefox node verification/compendium-smoke.cjs
# Repeat the four smoke commands with the corresponding *_ENGINES=webkit on macOS.
# Decode every original music file, not the new archive track.
find assets/birthday assets/album -type f \( -name '*.mp3' -o -name '*.m4a' -o -name '*.mp4' \) -print0 | while IFS= read -r -d '' f; do
  ffmpeg -nostdin -v error -xerror -i "$f" -f null - || exit 1
done
```

Run the smoke scripts themselves; they create their own test servers. Inspect results and console/network logs privately. Verify:

- Original landing and welcome; START, pause, replay, interruptions, original audio-timed flower opening, completion dialog and static fallback; correct artwork and no missing audio.
- Blossom growth/rendering, petals, reduced motion, lily reveal/interactions, album entry and navigation, queues/seek/track transitions, album and scrapbook return links, exact asset availability, original licensed fonts.
- Desktop and mobile viewport, zoom, orientation, touch, keyboard navigation, focus, contrast, screen-reader labels and reduced motion; capture private screenshots at 1440×900 and 390×844 plus physical mobile tests.
- Chromium, Firefox and WebKit automated checks, plus real Chrome, Edge, Firefox, macOS Safari, iOS Safari and Android Chrome; test user gesture, autoplay blocking, replay, native audio interruptions and asset range requests. Browser automation is not physical-device evidence.
- No unexpected console errors, failed requests, original asset leaks, public metadata disclosures or public CI artifact uploads. Verify unrelated homepage, tourbillon, collectibles, interactive worlds, Sofra and API behavior with existing suites.
- Compare public archive against exact approved wording, home destination, original unedited archive track and reduced motion; verify public archive remains available throughout. Run `node --test tests/memory-archive.test.mjs` and `node verification/memory-archive-smoke.cjs` in the archive checkout after installing Playwright 1.56.1 and full Chrome (`npx playwright install --with-deps chrome`; run with `CHROMIUM_EXECUTABLE=/usr/bin/google-chrome`). The bundled Chromium build may lack an AAC decoder. The archive browser harness serves the real files and licensed font over local HTTP. Verify real hosted headers/routes separately.

## 6. Rollback

Record the known archived state SHA and deployment identity privately before any future restore. If a private preview fails, remove its exposure/revoke access and stop the preview, keeping the restoration branch and backup private. In a private repository use a reviewed revert of the restoration commit(s) or a new branch from `ARCHIVE_SHA`, and verify the archived state; never reset or force-push public main blindly. For a production incident restore the approved archived deployment only after owner approval, not a historical deployment containing original content. Re-check that private asset routes are denied and the archive's exact text and song are intact. Preserve both the original verified bundle and any modified private restoration branch for diagnosis. Do not delete the backup.

## 7. Instructions to future AI agents

Read this guide and the restricted record before acting. Require explicit authorization and a verified source bundle. If the bundle, authorization, privacy controls or verified tests are missing, stop and document the blocker. Update the restricted record with the actual archive commit/date, preview approval and verification results only after those events are observed.
